03 · SYSTEM DESIGN

Built as a learning system, not a chatbot.

The browser handles presentation and student interaction. Authenticated serverless APIs orchestrate AI calls. Supabase stores the student model under Row Level Security. The AI layer is validated before its output can change learning state.

  • Anonymous-first onboarding with optional account linking
  • Server-side Gemini access; no provider secret in the client
  • RLS-scoped student data and authenticated API requests
  • Strict payload limits, rate limits, safety settings and structured AI validation
  • Server-side exam scoring so answer keys are not exposed to students

04 · 90-SECOND JUDGE FLOW

What a judge should see.

0–15s

Start

Tap Demo Mode. No signup friction. A populated student model appears instantly.

15–40s

Break a problem down

Ask a question or use a sample mistake. Fakkakha asks for the next reasoning step instead of dumping a solution.

40–60s

Expose the misconception

Mistake Detective identifies the first wrong step, why it fails, and a targeted practice prompt.

60–90s

Prove progress

Open progress / mistake patterns, then run Exam Mode to show measurable outcomes.

06 · WHY IT CAN SCALE

Model routing

Simple classification can use a faster model; complex teaching can use a stronger model.

Cost controls

Caching, input limits, rate limiting and bounded history reduce avoidable AI spend.

Trust layer

Structured output validation, safety settings, reporting and server-side state changes reduce failure modes.

Device continuity

Anonymous onboarding keeps friction low; optional email linking lets progress travel with the student.
